# Agnosia: руководство пользователя

> Agnosia помогает держать выбранные Android-приложения отдельно от основной части телефона.  
> Для этого используется **рабочий профиль Android** - отдельное пространство внутри системы со своими приложениями и настройками.

Идея простая: если приложению не нужно постоянно быть рядом с вашими личными данными, его можно перенести в рабочий профиль, запускать только когда нужно, а после использования снова скрывать.

---

## ⚙️ Как это работает

При первом запуске Agnosia предлагает создать рабочий профиль. Это стандартная возможность Android. Внутри такого профиля приложения отделены от личных приложений, личных аккаунтов и части данных основного профиля.

После настройки вы попадаете на экран **"Приложения"**. Там можно скопировать приложение в рабочий профиль, открыть его, скрыть, удалить из рабочего профиля или настроить для него дополнительные ограничения.

### Обычный сценарий для пользовательского приложения

| Шаг | Действие |
| --- | --- |
| 1 | Вы выбираете приложение в личном профиле |
| 2 | Agnosia копирует его в рабочий профиль |
| 3 | Agnosia предлагает закрепить ярлык для запуска; лаунчер может запросить подтверждение |
| 4 | При запуске через ярлык приложение запускается как обычно |
| 5 | Когда вы перестаёте им пользоваться или блокируете экран, Agnosia снова скрывает приложение |

Скрытое приложение не отображается как обычное приложение рабочего профиля, и Android ограничивает его запуск и работу в фоне.

---

## 🚀 Первый запуск

Нужен Android 12 (API 31) или новее с поддержкой рабочего профиля.

Во время первичной настройки Agnosia:

- проверит наличие рабочего профиля или создаст его
- попросит нужные системные разрешения
- откроет нужные разделы настроек Android
- после завершения покажет основной экран со списком приложений

Некоторые разрешения Android выдаёт только через системные экраны настроек. Это нормально: Agnosia откроет нужный раздел, а вам останется включить нужный пункт и вернуться назад.

### Способы создания рабочего профиля

На шаге рабочего профиля доступны три кнопки:

- **Создать профиль** — обычная системная настройка Android.
- **Создать офлайн** — системная настройка без подключения к интернету, доступна с Android 13.
- **Создать через root** — создание без системного мастера. Требуется работающий `su`; при запросе разрешите Agnosia root-доступ. После создания приложение установит рабочую копию, настроит профиль и проверит связь с ним.

Если root недоступен, выберите обычное создание. Если настройка прервалась, повторное нажатие **Создать через root** продолжит настройку профиля, созданного этой операцией. Чужой рабочий профиль приложение не изменяет. Если продолжение невозможно, удалите незавершённый рабочий профиль в настройках Android и запустите создание заново. Автоматически удалять профиль после ошибки Agnosia не будет.

Если Agnosia сообщает о неподтверждённом завершении root-команды, сначала перезагрузите устройство. Это необходимо, чтобы новая попытка не пересеклась с предыдущей командой. Уже полностью настроенный профиль повторно не создаётся: если он выключен, включите его в настройках Android.

### Зачем нужны разрешения

| Разрешение | Для чего нужно |
| --- | --- |
| **Рабочий профиль** | Создать отдельное пространство и управлять приложениями внутри него |
| **Статистика использования** | Понять, когда изолированное приложение уже не используется и его можно скрыть |
| **Уведомления** | Показывать служебные уведомления, когда это требуется Android |
| **Установка APK** | Копировать приложения в рабочий профиль |

**Доступ ко всем файлам**  Нужен только для File Shuttle, чтобы DocumentsUI мог передавать выбранные файлы между профилями

**Управление VPN** и **Поверх других окон** запрашиваются отдельно при включении модуля **VPN Guard**.

Если Android блокирует выдачу **истории использования** или **доступа поверх окон**, нажмите **«Не удаётся разрешить?»** рядом с разрешением. Откроются инструкция и кнопка **«Открыть настройки Agnosia»**. Для истории использования она открывает рабочую копию Agnosia, для доступа поверх окон — основную. В меню ⋮ найдите **«Разрешить доступ к настройкам»** или **«Разрешить ограниченные настройки»**, затем вернитесь и повторите выдачу разрешения. Название и расположение пункта зависят от прошивки. Статусы обновятся после возврата; само открытие настроек не выдаёт доступ.

## 📱 Действия с приложениями

В карточке приложения доступны только те действия, которые подходят для текущего приложения и профиля.

**Личный профиль**

| Действие | Что означает |
| --- | --- |
| **Копировать в рабочий** | Установить пользовательское приложение в рабочий профиль или включить там системное |
| **Переместить в рабочий** | Скопировать пользовательское приложение в рабочий профиль и удалить его из личного профиля |
| **Удалить** | Удалить выбранное пользовательское приложение из личного профиля |
| **Разрешения приложения** | Открывает список разрешений приложения |

**Копирование и перемещение пользовательского приложения не переносят его данные:** Agnosia устанавливает APK в другом профиле, но не копирует настройки, аккаунты и локальные файлы. Перед действием **«Переместить в рабочий»** сохраните нужные данные личной копии: после подтверждения установки в рабочем профиле Agnosia удалит её из личного профиля.

Системное приложение из личного профиля можно включить в рабочем профиле, но Agnosia не создаёт для него ярлык и не скрывает его автоматически. Действие **«Переместить в рабочий»** для системных приложений недоступно.

**Рабочий профиль**

| Действие | Что означает |
| --- | --- |
| **Копировать в личный** | Скопировать пользовательское приложение из рабочего профиля обратно в личный; для системных приложений кнопка недоступна |
| **Создать ярлык** | Предложить закрепить ярлык для запуска приложения под управлением Agnosia |
| **Заморозить принудительно** | Скрыть приложение под управлением Agnosia через политику рабочего профиля |
| **Удалить** | Удалить выбранное пользовательское приложение из рабочего профиля; для системных приложений кнопка недоступна |
| **Изоляция Agnosia** | Включить или выключить управление пользовательским приложением через Agnosia; для системных приложений переключатель недоступен |
| **Разрешить обмен / Обмен включён** | Разрешить приложению запросить согласие пользователя через Android на межпрофильное взаимодействие или убрать это разрешение Agnosia |
| **Разрешения приложения** | Посмотреть актуальные разрешения, запретить отдельный доступ или снять запрет |
| **Заблокировать интернет / Интернет заблокирован** | Включить или снять блокировку сети для выбранного пользовательского приложения через модуль Lockdown |

> **Про обмен между профилями:** этот переключатель меняет список приложений, которым Agnosia разрешает запросить согласие на межпрофильное взаимодействие. Сам по себе он не открывает приложению файлы или контакты второго профиля: требуется поддержка этой функции приложением и согласие пользователя в системном запросе Android. Передача файлов через File Shuttle настраивается отдельно.

> **Про File Shuttle:** это отдельный модуль Agnosia для передачи файлов через системное приложение **Files / DocumentsUI**.
> Она не даёт файловым менеджерам прямой доступ к чужому `/storage`; файлы идут через безопасные `content://` URI Android.

> **Про изоляцию Agnosia:** переключатель показывает или скрывает пользовательское приложение рабочего профиля. Если выключить изоляцию, приложение станет доступно в рабочем профиле для обычного запуска. Такой запуск вне Agnosia не создаёт отслеживаемую сессию: автоматическое скрытие после использования и VPN Guard для него не сработают. Запуск через карточку Agnosia или её ярлык по-прежнему создаёт отслеживаемую сессию и может снова скрыть приложение после использования.

### Передача файлов между профилями

File Shuttle показывает корень второго профиля в системном **Files / DocumentsUI**. В личном профиле можно открыть рабочие файлы и копировать их в обе стороны через Files. Провайдер также публикует личные файлы в Files рабочего профиля, но интерфейс Agnosia в рабочем профиле не открывается.

Чтобы функция работала:

| Что включить | Где |
| --- | --- |
| **File Shuttle** | На экране **«Модули»** |
| **Доступ ко всем файлам** | В личном профиле |
| **Доступ ко всем файлам** | В рабочем профиле |

После этого в личном профиле откройте модуль File Shuttle, нажмите **«Открыть Files»** и выберите корень рабочего профиля. На новых версиях Android ручной запуск системного Files, в том числе из рабочего профиля, может не успеть поднять межпрофильный bridge из-за ограничений фонового запуска Activity. Кнопка Agnosia предварительно подключает bridge для личного профиля.

Если root второго профиля пуст или Files показывает ошибку, проверьте:

| Причина | Что проверить |
| --- | --- |
| File Shuttle выключен | Включить модуль на экране **«Модули»** и дождаться синхронизации с рабочим профилем. |
| Нет доступа ко всем файлам | Выдать `Доступ ко всем файлам` Agnosia в обоих профилях. |
| Files открыт вручную, и bridge не подключился | Закрыть Files и снова открыть его кнопкой **«Открыть Files»** в модуле File Shuttle. |

### Ярлыки скрытых приложений

После скрытия приложения его обычный ярлык может пропасть с экрана смартфона. Agnosia предлагает закрепить собственный ярлык, через который можно снова открыть приложение. Подтвердите его добавление, если лаунчер попросит об этом.

Когда вы нажимаете такой ярлык:

1. Agnosia "размораживает" приложение.
2. Запускает его.
3. Следит за его работой.
4. Когда приложение больше не используется, "замораживает" его.

Если вы заблокируете экран во время активной сессии скрытого приложения, Agnosia пытается завершить эту сессию и снова скрыть приложение. Остальные приложения рабочего профиля эта операция не замораживает.

### Разрешения и риски

Agnosia показывает разрешения приложения и отмечает потенциально опасные сочетания.

Оценка риска на карточках приложений доступна при включённом модуле **Risk Engine** на экране **«Модули»**. Список разрешений можно просматривать отдельно.

Например, приложение с доступом к геолокации, работе в фоне и интернету может быть более рискованным, чем приложение только с доступом к интернету.

> **Подсказка, а не приговор:** оценка риска помогает понять, на что стоит обратить внимание. Окончательное решение всё равно остаётся за вами.

В разделе **«Разрешения приложения»** показаны все разрешения, которые приложение заявляет Android: запрашиваемые во время работы, выдаваемые при установке и специальные доступы. Список берётся из установленного приложения. Сначала идут более чувствительные runtime-разрешения, затем специальные доступы и остальные разрешения; внутри группы выданные показываются первыми. В рабочем профиле доступны поиск по названию или идентификатору и кнопка **«Обновить статусы»**. В личном профиле для каждого разрешения показаны только название, техническое имя и описание.

Понятные названия и короткие объяснения берутся из отдельного словаря. Он включает разрешения Android, Health Connect для приложений начиная с Android 9, рекламные разрешения и распространённые разрешения старых APK. Если записи в нём нет, показано **«Неизвестное разрешение»** и техническое имя; Agnosia не придумывает объяснение для непроверенных разрешений производителей и сторонних приложений.

В рабочем профиле каждая строка показывает актуальный статус: **«Выдано»**, **«Не выдано»**, **«Запрещено»**, **«Выдано политикой»** или **«Статус недоступен»**. Разрешения рабочего приложения читаются внутри рабочего профиля при открытии раздела, возвращении в Agnosia и после изменения. Если обновление не удалось, старые действия убираются и отображается ошибка.

Кнопка **«Отозвать»** снимает уже выданное runtime-разрешение без постоянного запрета: приложение сможет запросить доступ снова. **«Запретить»** также отзывает доступ, но блокирует повторные запросы. Можно запретить и ещё не выданное разрешение. **«Снять запрет»** возвращает обычное управление Android: доступ автоматически не выдаётся.

Для выданных разрешений, которые нельзя отозвать отдельным действием Agnosia, рядом со статусом показано **«нельзя отозвать»**, а кнопка **«Отозвать»** отсутствует. Например, обычные manifest-разрешения и специальные доступы нельзя менять этими кнопками. Для старых приложений с прежней моделью разрешений может быть доступен только постоянный запрет. Закреплённые системой runtime-разрешения Android также может отказаться менять: Agnosia покажет отказ и заново прочитает статус. Если Android не раскрывает состояние специального доступа, отображается **«Статус недоступен»**. В личном профиле этот раздел работает только для просмотра.

## 🔐 VPN и рабочий профиль

Некоторые приложения пытаются понять, используется ли VPN. Если перед запуском приложения из рабочего профиля VPN нужно временно отключить, Agnosia может сделать это автоматически, а после завершения снова включить выбранный VPN-клиент.

### Модуль Lockdown

Lockdown блокирует интернет выбранным приложениям рабочего профиля. Сначала включите модуль **Lockdown**, затем откройте карточку рабочего приложения и включите переключатель блокировки интернета.
Модуль включается на экране **«Модули»**.

Модуль использует системный режим Android **always-on VPN + lockdown**. Для приложений без блокировки Agnosia разрешает прямой доступ к сети рабочего профиля. Приложения, у которых включена блокировка интернета, остаются внутри технического Lockdown VPN без проксирования трафика и поэтому не получают сеть.

Если приложение было скрыто, Agnosia обновляет Lockdown-политику после временного восстановления приложения перед запуском. Это нужно из-за поведения Android: скрытый пакет может временно выглядеть как несуществующий для VPN allowlist.

### Модуль VPN Guard

Откройте **«Модули» → «VPN Guard»**, выполните требования модуля и выберите VPN-клиент.

| Настройка модуля | Что делает |
| --- | --- |
| **Включить модуль** | Перед запуском пользовательского приложения рабочего профиля через Agnosia временно отключает активный VPN, а после скрытия приложения отправляет команду запуска выбранному VPN-клиенту. Системные рабочие приложения запускаются без этого сценария. |
| **VPN-клиент после заморозки** | Выбирает клиент, которому Agnosia отправит команду запуска после заморозки рабочего приложения. |
| **Токен Tunguska Automation** | Используется только для Tunguska, если выбран этот клиент. |

Когда VPN временно отключён, Agnosia показывает небольшой полупрозрачный **синий квадрат** в правом верхнем углу экрана. Это связано с ограничениями Android и не влияет ни на что.

Перед отключением активного VPN Agnosia проверяет, сможет ли отправить выбранному клиенту команду восстановления. Если обработчик недоступен, запуск останавливается с сообщением о клиенте; активный VPN сохраняется.

Если подтверждение запуска потерялось, Agnosia проверяет рабочую сессию перед восстановлением VPN. Отправка команды VPN-клиенту сама по себе не означает подключения: Agnosia ждёт обнаружения VPN и сохраняет повтор при неудаче.

### Поддерживаемые VPN-клиенты

Поддерживаются FlClash (`com.follow.clash`), Clash Meta, Happ, Tunguska, INCY, Exclave, husi и NekoBox+.

Для Tunguska нужно дополнительно указать токен автоматизации. Без него Agnosia не сможет отправить команду запуска.

Happ принимает только команду переключения: если VPN уже подключён, повторная команда может его отключить. Agnosia показывает предупреждение при выборе такого клиента.

## ⚙️ Настройки приложения

### Тема

| Тема | Как выглядит |
| --- | --- |
| **Красная** | Фирменная тёмная тема Agnosia с красным акцентом. |
| **Темная** | Спокойная тёмная тема. |
| **Светлая** | Светлая тема. |

Тема применяется сразу и сохраняется для следующих запусков.

### Транспорт команд

В разделе **«Транспорт команд»** выбирается способ выполнения команд в рабочем профиле. Обычно оставляйте **«Авто»**.

| Режим | Что происходит |
| --- | --- |
| **Авто** | Для поддерживаемых команд Agnosia использует Provider и при безопасном сбое пробует Activity. Остальные команды выполняются через Activity. |
| **Provider** | Команды командного центра отправляются только через Provider. Если команда им не поддерживается или соединение недоступно, действие завершится ошибкой без автоматического перехода на Activity. |
| **Activity** | Команды командного центра выполняются через Activity. |

При первом подключении Provider Android может кратковременно открыть служебный экран Agnosia, чтобы выдать доступ между профилями. Интерактивные действия, например установка приложения с системным подтверждением, всё равно открывают Activity независимо от выбранного режима. Выбор сохраняется и применяется к следующим командам.

### Поведение

| Настройка | Простое объяснение |
| --- | --- |
| **Показывать все пакеты** | Показывает не только обычные приложения, но и системные или служебные пакеты |
| **Включить логирование** | Записывает последние события работы Agnosia во внутренний журнал |

File Shuttle, Lockdown, VPN Guard и Risk Engine включаются на отдельном экране **«Модули»**.

## 📝 Журнал событий

Журнал событий - это короткая история последних действий и ошибок Agnosia. Он нужен для диагностики.

Чтобы открыть журнал, нажмите на название приложения в верхней части экрана. Если включена опция **«Включить логирование»**, в журнале можно просмотреть, скопировать или очистить диагностические записи.

Скопированные записи можно приложить к сообщению об ошибке. На слабых устройствах логирование может немного снижать производительность, поэтому после диагностики его можно выключить.
